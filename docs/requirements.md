# 已确认需求与第一版边界

## 使用对象

两位指导大数据、人工智能相关本科毕业论文的老师；学生各自固定对应一位老师，专业和研究方向可能不同。老师主要使用 Word 的批注、修订。

## 减负目标

- 第一位老师主要希望减轻格式规范（C）与语言表达（A）负担，同时认为论证结构（B）应优先关注。
- 第二位老师的优先级为 D、C、B、A；D 指自动指出和解释学生反复出现的同类问题，优先考虑历次稿件，而非仅当前稿件。
- 第一版以 D 为核心体验，以 C、A 为最先做扎实的检查内容；B 提供重点提示，重大问题优先呈现。

## 最小流程

1. 接收某名学生的历史稿件、教师意见、新稿及适用规范。
2. 将原批注、修订与原文上下文整理成候选历史问题，用规则生成类型、摘要、范围和期望改法，允许教师确认、修正和停用。
3. 审查新稿：先用字符串召回历史候选；有密钥时由 Pi 判断是否同一条问题，Python 只校验原文后再写批注。同一密钥下，Pi 再对关键主张是否被实验或数据支持做多步取证；主张或证据原文对不上、证据不足或模型失败时不写论证批注。有密钥但 Pi 调用失败时，格式规则可离线补上，历史复犯不写。这还不是四类论证问题都审完。输出问题位置、理由、建议改法、历史或规范依据。
4. 在 Word 副本内呈现批注；适合文字修改的建议使用修订，由老师接受或拒绝。

一次局部修订不自动成为通用规则；没有历史证据不称为“再次犯错”。历史记录按老师与学生区分，并保留稿件版本和来源。

## 模型和发布决定

- 计划采用 pi 的多提供方模型接入能力，让老师选择兼容模型。
- 允许向云端模型发送用于审改的论文内容；不意味着把这些内容发布到 GitHub。
- 以工具调用、有效结构化结果、错误处理和实际审改质量验证兼容性；不同时启用多个模型审同一篇作为首版必需功能。
- 模型 API 的账户、费用和额度取决于老师选择的提供方；具体配置与预算控制待实现。
- 原创内容采用 MIT，作者计划不售卖、免费提供给学校使用。允许下游按照 MIT 使用，包括商业使用。
- 正式部署方式尚未锁定，先做可在本地验证的小流程。

## 第一版不做

全文代写、自动评分、自动判定创新性、学生能力画像、任意学校模板一键修复、完整在线 Word 编辑器，以及多 agent/多模型裁决平台。

## 材料到位情况

- 大连财经学院 2026 届通知、指导手册和格式标准已取得。可自动判断的条款写入 [dalian-finance-2026.md](dalian-finance-2026.md) 与代码检查；学校文件全文不进本仓库。
- 同一学生多轮带批注 Word 稿已在本机对照，用于收紧历史匹配。真实学生论文、教师批注和私人历史库留在本地 `artifacts/`，不提交。
- 公开测试仍只用模拟稿（演示学生「小周」）。

## 验收

观察有效建议比例、重复问题的识别质量、教师核对与驳回意见后的总耗时，以及 Word 文件可打开、原文定位正确、原有批注修订与排版得到保留。具体质量门槛取得真实样稿和人工基线后确定。
